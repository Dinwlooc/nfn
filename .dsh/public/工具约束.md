2. 递归与批量操作一律加静默错误开关，错误重定向到文件只读尾部，绝不直接刷屏。

## 失败处理

8. 失败先分类：确定性错误不重试，可重试错误设上限与退避，部分成功先查副作用。
10. 越权操作一次性向 Owner 说明代价并等待授权；被拒后不换法重试。
13. 重读前先校验上下文副本：`node .dsh/trust.mjs <路径...>`；FRESH 可信直接复用，STALE 重读，MISSING 或 UNSEEN 重新获取。无参数列出本会话读过的文件。

## 本环境已知签名（观察到的事实，命中即按既定处置，不现场诊断）

14. `tool_search` 返回空 `matches` 表示"没有更多隐藏工具"，不是"没有工具"；已可见的工具直接调用，不要因此重试或改写查询（实测：弱 AI 把空结果读成"未配置"）。
15. 子代理的完成信号不可信：弱模型的会话常以空工具调用收尾并标记失败，而文件已落盘；验收一律看产物（文件内容/哈希/校验器），不看会话状态。
16. 空工具调用是本环境的已知致命签名：会话日志末条 `tool/call` 的 `name`/`callId` 为空时，引擎报 `unknown tool ""`，随后写出不匹配的 `tool/result`（`format v4 ... requires toolCallId matching its tool source`），该轮不可分支。处置：该会话作废、状态回文件、开新会话；不要在同一日志上重试或分支。（deepseek-flash ｜2026-10-24 补，依据 13:02 lead 会话与 4 次子代理复现）

## 读取调优规则

1. 先定位后读：跨文件找线索用 shell 或 grep 只取匹配行，确认位置后再用 read 加 offset/limit 读片段。
2. 单次 read 控制在约 200 行或 1.5k token 内；超过 2k token 的结果分页，或换 shell 过滤。
3. 重读前先跑 `node .dsh/trust.mjs <路径...>`，FRESH 直接复用。
4. MCP 工具读优先字段级与 op 级取数，不用整文件 read_text。
5. shell 一命令多用，合并多次查询。

## 写策略

1. 局部改动用 edit，锚点带上下文，保证唯一。
2. 新文件或小文件近乎重写才用 write；超过约 100 行的整文件重写不用 write。
3. 同一模式批量改四个以上文件用脚本，脚本内放断言。
4. write 与 edit 前都要先 read；陈旧读会拒绝写入，重新 read 后再改，不盲目重试。
5. 短锚点命中多处时换更长锚点，或显式 replace_all。
