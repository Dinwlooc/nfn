# 0025 自校准框架对照：META 与市场记忆/进化类插件

keywords: 自校准,META框架,证据门,执行点,rule-engine,evolution-lab,mneme

**摘要**：把四个记忆类插件与三个"自进化/规则执行"类插件当作自校准框架的参照物读了一遍。结论：**没有能替代 META 的工具**——它们缺类型路由、多模型归属与签发审计；但 META 有两个它们已经工程化的空缺：**行为执行点**（靠自觉 vs 工具守卫硬阻断）与**证据门**（改完再审计 vs 先 A/B 再激活）。可借的是这两个机制，以及"冲突冻结"的建模方式。证据为 README/源码结构与 GitHub 元数据，**未实装**。

## 0. 结论

1. **框架类型不同**：META 是**规范型**（定义判据、口径、契约，按任务类型路由，写入要签发）；市场工具是**经验型**（从轨迹挖经验、自动改写技能）。规范型不能被经验型替换，只能被补强。
2. **META 独有的三样，市场没有等价物**：① 六类型路由 + 必读清单；② 多模型库与写权限归属（会话存储定身份）；③ 签发制（sha8 + revisionBasis，事后可审计）。
3. **市场已工程化而我们没有的两样**：① **执行点**——`dsh-rule-engine` 把 AGENTS 规则解析成工具守卫，违规调用**同步硬阻断**；我们的规则全靠模型自觉，校验器只做事后格式检查。② **证据门**——`dsh-evolution-lab` 的闭环是"候选 → 隔离 A/B（passΔ≥0.05、cost≤1.2×、时长≤1.5×）→ 留出 canary → proof → 原子激活 → 定时探测 → 回归自动回滚"，且**模型只能读状态，不能决定 winner**；我们的提示词改动没有 A/B，"可证伪"只写在 META 策略里。
4. **可立刻借的两个建模**：冲突冻结（mneme `conflictFreeze`：矛盾不自动裁决，进队列人工选边）与失败记忆（mneme `failure_memories`：用户纠正记旧值/新值，为后续进化积累数据）。
5. **不建议整包引入**：`dsh-evolution-lab` 只验证到 DSH 0.1.0-rc.6（我们是 0.2.1-rc.3）；`dsh-rule-engine` 只认宿主全局 AGENTS.md（家目录版）（我们的规则在项目根 AGENTS.md）；`@lmzhen/dsh-evolution-host` 虽有 rc.3 兼容的 engines，但 23 个子包、★5，复杂度不划算。

## 1. META 的骨架（对照基准）

| 柱 | 落点 | 机制 |
|---|---|---|
| 类型判定 | `public/meta/分类标准.md` | 六类型互斥 + 协作维度叠加 |
| 路由 | `meta_route` 两跳 | 按模型×类型发**路径清单**，正文不内联（防压缩失真） |
| 契约 | 论文头部 | 标题 + keywords + 摘要；字段收缩为可检索最小集 |
| 审计 | `meta_sign` | 时间戳+模型+revisionBasis+sha8 入 `.revlog.md`；**只记账不拦截** |
| 腐化判据 | 0021 + `custom_tools/check/*` | 编码损坏 / 死指针 / 索引漂移 |
| 成本纪律 | OL1H + budget-watch | H 席位按能力→单价→可用性现算；预算按会话记账 |
| 自调优 | META 策略宗旨 2 | 发现提示词失效**当场修订并签发**，不等下轮 |

## 3. 结构差异（为什么不能互换）

| 维度 | META | 记忆/进化类插件 |
|---|---|---|
| 真相源 | 文件 + 签发链（谁写的、凭什么、哈希多少） | 证据分数 / LLM 摘要 / 聚类 |
| 写入权 | 分模型分文件，正文由作者签发 | 模型自写、后台自整理 |
| 路由 | 按任务类型取必读，**确定性** | 按相似度召回，**概率性** |
| 生效时机 | 写完即生效，事后审计 | 评测通过才激活（eval 类），或立刻注入（memory 类） |
| 失败处理 | `state: superseded/refuted` 单条标记 | 冲突冻结 / 自动回滚 / 归档 |
| 单位 | 判据、口径、契约 | 偏好、历史、教训 |
| 成本 | 预算账本 + 席位单价 | 后台 LLM 摘要与巩固（多数默认开） |

## 4. 三个可落地的补强（按性价比排序）

1. **冲突建模（今天就能做，零依赖）**：论文头部增 `conflicts: [NNNN]`（可选），校验器双向校验并拒收单边声明。解决"两篇论文互相矛盾但都 active"的现状。
2. **行为执行点（中成本）**：把 AGENTS 里**机器可判**的少数几条（无预算禁止批量删除、"读回写"探针禁令、改前必须 read、预算超额即停）做成守卫/校验器，而不是靠自觉。可参考 rule-engine 的"守卫 + 审计台账"形态，但**不装它**（全局 AGENTS 路径不匹配、误判风险）。
3. **证据门（高成本，需任务集）**：任何达阈值的提示词改动，先写"预期效果 + 失效条件"，再按 evolution-lab 的 EvalTask 契约跑 baseline/candidate 对照。即使不装插件，也可复用它的**任务契约与阈值口径**（passΔ、cost ratio、canary 留出）。

## 5. 不建议

- 用记忆插件替代知识库：召回对象是它自己的库，且会引入无签名的第二真相源（详见 0024）。
- 装 `dsh-evolution-lab`：与我们 DSH 版本不兼容；等它进 0.2.x 支持矩阵再评估。
- 装 `dsh-rule-engine`：全局 AGENTS 与我们项目级规则错位，且其语义判定本身要花模型调用。

## 6. 未验证

- 三个执行/进化类插件均**未实装**；兼容性判断来自 README 的版本矩阵与 `engines`，不是 smoke test。
- `@lmzhen/dsh-evolution-host` 只看了 manifest 与描述，23 个子包的实际服务面没读。
- "证据门"落地所需的 EvalTask 数量与成本，本项目没测算。
