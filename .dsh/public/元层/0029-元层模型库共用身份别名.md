# 0029 元层模型库共用：身份别名

keywords: 元层,模型库,共用,别名,modelAliases,meta_alias,身份,跨系

**摘要**：同族模型各自从空库开始重长 must-read，是本项目实测到的重复劳动（`deepseek/deepseek-reasoner` 0 文件、`deepseek/deepseek-v4-pro` 1 文件，而 `deepseek/deepseek-flash` 26 文件）。Owner 2026-10-28 裁定：**本项目 DeepSeek 全系共用 `deepseek-flash` 一库**；跨系别名通常不兼容但**不得硬编码制止**。实现为"身份别名"：`model` 保持事实（上报/revlog），`identity` 决定路由与库目录；配置是 `.dsh/meta/config.json` 的 `modelAliases`，模型经新工具 `meta_alias` 自行维护。

## 1. 机制

| 概念 | 含义 |
|---|---|
| `model` | 会话真实模型（`request/context` 的 `model`），**只用于上报与 revlog 署名** |
| `identity` | 解析别名链后的库身份，**决定 `modelDir` 与建库位置** |
| `modelAliases` | `{ "<原始模型名>": "<身份模型名>" }`，项目级单一事实源 |

- 链式解析、防环、深度上限 8；**环或超深一律回落到原始模型**并给出 `aliasWarning`（坏的配置不能把路由打挂）。
- `readProjectConfig` 中 `modelAliases` 与 `revlogEntries` **互不连坐**：一个坏不影响另一个。
- 归一是"丢弃脏值"而非报错（弱模型容错）。

## 2. 为什么不是别的方案

- 目录符号链接/junction：Windows 上容易被误删、`.dsh` 里的 junction 还会撞上 `confine` 的 realpath 校验。
- 首次使用复制库：两份会立刻分叉，修订日志也分叉，比不共用更糟。
- 身份别名：**只有一份真实目录**，事实与身份分离，审计仍能看到是哪个模型改的。

## 3. 维护工具 `meta_alias`

`list | set | remove`，写 `.dsh/meta/config.json` 时**保留其它键**（`version`、`revlogEntries`）。

- 允许跨系（只给 warning，不拒绝）——Owner 口径。
- 只拒绝：空值、`from === to`、会成环的 set。

## 4. 现行配置（本项目）

```json
"modelAliases": {
  "deepseek-chat": "deepseek-flash",
  "deepseek-reasoner": "deepseek-flash",
  "deepseek-v4-pro": "deepseek-flash",
  "deepseek-v4-flash": "deepseek-flash",
  "deepseek-v41-flash": "deepseek-flash",
  "deepseek-v4.1-flash": "deepseek-flash"
}
```

依据：本项目近 300 条 `request/context` 里 DeepSeek 系出现过这 6 个名字（含 `v4.1-flash`/`v41-flash` 两种写法）。glm 系未加别名——`glm-4.6v` 与 `glm-5.3-flash` 是否同质未裁定。

## 5. 生效与验证

- **必须重装才生效**：meta-tools 是 link 安装，改代码后 `remove_bundle dsh-meta-tools` → `install_bundle link:…`（宿主进程启动于改动之前时尤其如此；今天就是 18:21 的进程跑着 22:47 的文件）。
- 实测：`meta_alias list` 返回 6 条；`meta_route` 返回 `model=deepseek-flash, modelDir=.dsh/deepseek/deepseek-flash`；回归 `RESULT run.mjs: pass=20 fail=0`（含"别名路由到目标库、model 保持事实、不 fork 源模型目录、跨系允许、防环拒绝、其它键保留"）。

## 6. 已知边界（如实记）

1. **共用是真共用**：模型拿到目标库的真实路径，能用原生 `write/edit` 改它——工具层无法做只读隔离，只能靠规则 + revlog 记录真实模型名做审计。
2. 未在真实 `deepseek-reasoner` 会话上跑过（本项目暂无该模型会话），别名路由目前只有夹具证据。
3. 跨系别名若指向不存在的族目录，会在目标族下建库；语义上"可用但不推荐"。
4. `meta_alias` 不做并发写保护（配置文件是单写者场景）。
