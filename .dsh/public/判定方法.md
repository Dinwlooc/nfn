# 判定方法：证据、改动与验证

keywords: 判定方法,证据分级,改动纪律,独立通道,结论封顶,假证据,授权边界

**这份文件回答一个问题**：凭什么说一件事"成立"。它不重复各类型细则，只给跨类型通用的判定骨架；细则里的具体判据优先。

## 一、三段定位（动手前先定）

1. **任务类型**：元层 / 架构 / 业务 / 插件 / 杂务 / 算法——六选一，互斥。判据见 `meta/分类标准.md`。
2. **协作类型**：协作 / 独立。独立只有 OL1H 一种策略（`meta/OL1H策略.md`）。
3. **验收判据**：写清楚"怎么算做完"+ 证据类型（编译？校验器？计数？回读？）。**没有判据不开工**。

## 二、证据分级（越靠上越硬）

1. **机器输出**：编译/启动退出码、校验器的 fail 计数、工具统计、git 探针。可复跑即成铁证。
2. **实物回读**：改完用独立路径读回（不同工具、不同次读取），确认落地内容与意图一致。
3. **他人审查**：H 或其他模型给出的结论。它只能**指出可能错**，不能替代机器输出；H 的清单可能不全（实测：报 7 对双向依赖，实为 20 对）。
4. **自我复述**：最弱。会话状态、自己说"已经改好"、记忆里的印象，都不构成证据。

**假证据清单**（都真实踩过）：
- `--check-only --script` 在依赖编译失败时仍返回 0 → 不能当"编译通过"。
- 子代理/会话"完成"信号 → 只证明进程结束了，不证明文件对了。
- 编辑器"扫到了文件" → 不证明 `class_name` 已注册。

## 三、改动纪律

- **授权边界**：法层（`NFN-AIGC规则-*.md`、`AGENTS.md`）只 Owner 可改；知识库可交叉编修，但改动后必须 `meta_sign` 签发（印章是唯一署名）。
- **先备份再批量**：批量改/删前把原件存 `.dsh/experiments/<日期>-<事由>/`，损坏或误改可回退。
- **一次一件**：一次只做一个可验收的切片；不并行三件以上，不顺手重构。
- **小步闭环**：小批量写入 → 立刻读回；失败先定位最早根因，不在同一处堆叠重试。

## 四、独立通道

- 产出与验收必须**走不同通道**：写文件的用 `edit`，验收就用 `read`/校验器；改代码的用编辑器，验收就用 headless 启动。
- 同一通道自证不算独立（自己写、自己读、自己说对）。
- 审查通道（H）与产出通道分离：H 只读，不改文件。

## 五、结论封顶

**结论不得强于证据**：

- 有机器证据 → 说"已验证"+ 证据。
- 只有回读 → 说"已落地，未跑功能验证"。
- 只有推断 → 说"未验证"并写清假设。

对照表（本会话实例）：

| 声明 | 需要的证据 |
|---|---|
| "编译通过" | boot 退出码 0 且 `SCRIPT ERROR` 计数 0 |
| "知识库一致" | 校验器 `fail=0`（含 `--self-test` 通过） |
| "命令可用" | 至少一次真实调用链跑通；只有构造代码时写"未验证" |
| "数字准确" | 与工具输出逐格对齐；对不上就标注差异来源 |

## 六、复查顺序（收尾时）

1. 产物回读；2. 跑机器判据；3. 写笔记并签发；4. 报告"改了什么 / 验证了什么 / 还有哪些假设"；5. H 回执写席位（三大代码工作）。
