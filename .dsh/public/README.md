# 公共层 · 知识期刊

**定位**：可推翻的知识。根层 `.dsh/` 放项目法（owner 的硬约束，不可被 AI 推翻）；各模型库只放自己的特性、错误与调优。

## 结构（按任务类型分目录；与模型元层同构）

| 目录 | 类型 | 收什么 |
|---|---|---|
| `元层/` | 元层 | 元层细则与协作/调度类知识（协作维度知识并入此目录，Owner 裁定 2026-10-27） |
| `算法/` | 算法 | 计算调优、性能、帧处理相关论文 |
| `杂务/` | 杂务 | 注释与审验细则 |
| `架构/` | 架构 | 架构说明、架构指标定义 / 基线 / 判读 |
| `业务/` | 业务 | 功能实现与缺陷修复细则 |
| `插件/` | 插件 | DSH 插件/工具面论文 |
| `判定方法.md` | 通用 | 跨类型判定与证据方法（不属于单一任务类型，放在父层）——**文件已于 2026-10-27 前丢失**，见索引 0001；重建前勿按此路径取用 |
| `元层更新原则.md` | 通用 | 元层自身的更新规则 |

**每个类型目录下有 `细则.md`**——会话初始化按任务类型读它（meta_route 必读，v3 起只发路径，用原生 read 打开）。**模型库同构（2026-10-26 格式重构，Owner 裁定）**：模型库 = `.dsh/<系>/<模型>/`，根放 `meta.md`（二级 meta：自我校准、协作要点、协作者印象——独立/协作目录已退役并入此文件）；`<模型>/<类型>/` 放该模型该类型的校准与知识；`<模型>/记忆/` 放细节教训史（关键词 frontmatter 供 grep 检索）；模型目录由 meta_route 首跳补建（v3 起无字符常量、无登记表）；机读任务类型注册表 `.dsh/meta/tasktypes.json` 由模型经 `meta_tasktype` 维护。公共层 `public/<类型>/` 与 `<系>/<模型>/<类型>/` 同构；公共层是模型层的扩展；子文件夹是父文件夹的扩展（越具体越深）。

## 论文格式（`类型目录/NNNN-标题.md`）

```
# NNNN 标题

keywords: 逗号分隔的检索词（含中英同义词与场景词；检索走 `grep` 限定 `path` 至 `.dsh`，本行是主索引）

正文：摘要段（首句写结论，供直读起跳）→ 主张（编号，带证据、反例/边界）→ 适用范围 → 复核方式
```

- **不写头部字段块、不写文末署名、不写修订记录**：作者、日期与每次改动一律由 `meta_sign`（印章/签发）记进伴生 `<文件名>.revlog.md`；正文只留内容。
- **不写版号与状态**：生命周期（有效 / 被取代 / 被推翻）由印章的修订注记与索引「一句话」列说明，不在正文维护。
- 一条内容能进知识库，当且仅当它能改变未来的一次决策；叙述性过程写 `.dsh/experiments/` 或模型 `记忆/`。
- 描述项目代码的论文，在正文首段写一行 `基线：<sha8>[+]（日期）` 或 `基线：n/a`（不描述代码）；这是正文事实，不是头部字段。**`+` 表示写作时工作区有未提交改动**（含写作者自己的改动）：读者先比哈希判断内容是否同代，带 `+` 则须核对它是否已被后续提交覆盖。

## 交叉编修与冲突

1. 任何 AI 可改任何论文，但须：改动后立刻用印章记录（谁/何时/改了什么/为什么）；与他文冲突时点名对方编号与版号并说明取舍。
2. 两篇活跃论文不得静默并存矛盾主张：改到一致 → 择一（另一篇 `superseded` 压缩为指针）→ 证据硬者留，相当则有请把关人。
3. 保留原作者与结构、逐处打修正标记并署名；整篇重写＝另起新论文。

## 生命周期（不保留旧知识）

- **修订（superseded）**：正文压缩到只留差异，顶部写"被 NNNN vX.Y 取代"。
- **推翻（refuted）**：旧文压缩为三行指针；owner 可要求直接删除。
- **清理**：无引用、无证据、无人维护的可删；删前把索引行改记为"已清理（原主张…由…推翻）"。
