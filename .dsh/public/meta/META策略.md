# META 策略（元层设计宗旨）

keywords: META策略,元层存在理由,提示词演进,设计宗旨

## 宗旨

1. **提示词是工程制品，不是记录**：元层里的每一条都必须能改变未来的一次决策——改变一次选型、拦截一次重复踩坑、缩短一次判定。写不进这条标准的，进记忆档案或直接不写。
2. **鼓励自主调优**：AI 在任务实践中发现提示词缺失、过时、不可执行或与实例不一致时，**应当场修订并入库**（原生工具写改 + `meta_sign` 签发留痕），而不是把修正留给下一次会话重交学费。调优不需要等待指令；涉统领性文件结构与他人主权时先问（见二级 meta 教训二）。
3. **面向未来的读者**：提示词的读者是未来的任务、未来的会话、乃至未来接入的模型。因此——**指路比内容重要**（细节会漂，指针要落在第一眼会看的位置）；**契约要可证伪**（校验器校位置、非空、占位符，不是字符串出现与否）；**共享文书只写"如何确定"，不写"当次事实"**；**身份与旧认知一律当次确认**（接管即重启：系统提示重读身份、前任结论当主张不当先验、机器判据重跑）。
4. **演进循环**：实例一致 → 凝缩为规则 → 规则传向新实例；不一致即演化中 → 停下来问。权威顺序：**当次确认的把关人 > 实例一致性 > 规则凝缩**。文档也是凝缩，不是免检牌——标注来源只是下限，能实测就实测。

## 调优质量线（修订提示词时的判定纪律）

- **结论等级不得高于证据等级**：单实例不是证据，一致性才是；任何"失败"必须换通道复核才能升级为结论。
- **授权范围 = 可做集合**，越界收益再大也不做；问题进清单，修复是另一次授权。
- **可逆改动优先**（先注释、后顺序、最后结构）；一次到位，中途态产生的"证据"作废。
- **没有理想 oracle 就造机器可判定的替代物**；验证预算有界（同一路径最多两次有界尝试，不成换 oracle 或明说"未验证"）。
- **一条内容能进提示词，当且仅当它能改变未来的一次决策**；搬家不算过滤，必须逐条过筛。分工不漂移：方法（META 策略）→ 类型细则（`public/<类型>/`）→ 工程事实（领域知识）→ 实例与专名（记忆档案）。
- **可发现性不能靠自觉**：新规则必须挂在路由能带到的地方（meta/ 强加载或类型细则），指针越短越好。

## 适用与证伪

适用于本元层一切提示词的撰写、修订与淘汰；新范式尚无实例时一致性退化为零证据，直接问。任一条宗旨可被反例 + 对照例证伪，附可重跑的实验；被取代的条目以新文为准。
