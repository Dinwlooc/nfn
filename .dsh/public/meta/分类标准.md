# 分类标准

keywords: 任务类型,分类标准,互斥,协作类型,判定,meta_route

## 六任务类型（互斥，一次只取一个）

| 类型 | 判据（一句话） | 不属于它时 |
|---|---|---|
| 元层 | 改 `.dsh/` 元层本身：结构、路由、索引、插件化元工具 | 改的是业务代码 → 架构/业务 |
| 架构 | 判定结构、路径、扩展点、指标；产出论文或判读 | 写功能代码 → 业务 |
| 业务 | 按既有架构写/修功能与缺陷 | 结论是结构性的 → 架构 |
| 插件 | DSH 插件/工具/技能面的构建与审计 | 游戏内功能 → 业务 |
| 杂务 | 注释、审验、搬运、清点等机械作业 | 有判定成分 → 对应类型 |
| 算法 | 计算调优、性能量化与监控 | 无量化判据 → 架构/业务 |

## 协作维度（叠加在任务类型之上）

- **协作 > 独立**：协作 = 多 AI 协作（含模型测试），先读自己的二级 meta 协作节与协作者印象；独立 = 缺省，策略只有 OL1H（全类型必读）。
- 「协作」**不是任务类型**（Owner 裁定 2026-10-27）：它是叠加维度；协作方法住各自二级 meta 与 OL1H 策略，原协作类知识已并入 `public/元层/`，类型入注册表墓碑（`.dsh/meta/tasktypes.json` removed）。
- 模型库不再分独立/协作目录：印象、协作要点、自我印象都住在 `<系>/<模型>/meta.md`。

## 判定流程

1. meta_route 首调拿任务类型清单 → 2. 按上表定唯一类型 → 3. 二调取该类型必读 → 4. 拿不准报 Owner，不重开论证。
- 经 `meta_tasktype` 扩入注册表的新类型**不改变六类型的判定语义**：判定判据仍以本页为准，新类型只是多一条可路由的细则/知识目录。
