# 0021 预算账本按会话隔离：id 形态不是会话身份

keywords: budget-watch,会话隔离,账本,sessionId,子会话,并行会话,id形态,混账

**摘要**：`budget_register` / `budget_status` 默认只作用于**调用方会话**，输出首行固定回显 `session=<完整 id>`；并新增显式 `sessionId` 参数供父会话查子代理账本。根因不是"没按会话记账"——账本文件一直按 session id 落盘——而是**同一会话存在两种 id 形态**（`session-<uuid>` 与裸 `<uuid>`），主会话与子代理各用其一，读写若各拿一种形态就会分裂成两本账。

## 主张

1. **会话身份 = 文件里的 sessionId，不是请求参数的写法**。DSH 主会话的 `session.id` 形如 `session-22c0733c-…`，子代理是裸 uuid `9d158844-…`。读取时以文件内 `sessionId` 为准，写入时解析到**已存在的那个文件**：候选顺序 `<id>.json` → 另一种前缀形态；命中即固定，绝不新建第二本。
2. **消除并行混淆的最低成本手段是回显**，不是汇总：`budget_status` 首行 `session=<id>`，`budget_register` 回执同样带 id。模型先看这一行就知道账本归属；跨会话汇总反而制造"这数字算谁的"的新歧义。
3. **显式 `sessionId` 只改"看哪本账"，不改归属**。子会话默认写自己的账；父会话要查子代理，显式传参。参数只接受 `字母数字 . _ : -`，含 `..` 直接拒绝（路径穿越）；无 `session.id` 且未显式传参时**失败关闭**，不写共享的 `unknown` 账本——共享 unknown 就是并行会话互相污染的原点。
4. **子代理记账无需额外机制**（实测）：子代理内 `budget_status` 返回自己的裸 uuid 账本并已累计 11.7k tok，证明 `llm/stream` 的 `options.sessionId` 属于子会话，天然不串父账。
5. **测试夹具的期望值不能凭想象**（本项目第二次同型事故）：断言写成读第 2 行的 `session_total=…`，而无 task 分支根本没有该行（第 2 行是 money 行）。先跑一遍看真实输出，再决定断言行号——与 0019 主张 6 同类。

## 适用范围

`dsh-budget-watch` 及任何"按会话记账/计量"的工具（usage、审计、限流）。**不适用**：跨会话汇总报表的设计（那是另一条产品线，需要显式聚合键）。

## 复核方式

- 回归：`& <bundled node> dsh-plugins/budget-watch/test/run.mjs` → 29/29（会话维度四组：并行互不串账、显式跨会话只读、旧 `session-*.json` 被裸 id 读到且写回同文件、穿越 id 被拒）。
- 真机：`budget_status` 首行出现真实 `session=session-22c0733c-…`；`budget_status({sessionId:"session-6e3e0c5a-…"})` 只读另一本账。
- 子会话：起一个 flash 子代理令其调 `budget_status`，回报自身裸 uuid 且 `VERDICT: self-ledger`。
