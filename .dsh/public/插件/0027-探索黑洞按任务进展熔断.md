# 0027 探索黑洞：按任务进展熔断（dsh-exploration-guard v0.2）

keywords: 探索黑洞,任务进展,step,todo_write,goal,熔断,被动约束,dsh-exploration-guard

**摘要**：Owner 否掉了"同参数连续调用"的判据，给出真实轨迹：模型卡住时不重复，而是**不断换新调查**——找源码、解包 asar、写临时脚本、换假设、命令失败重试——每一步都有产出，任务节点却不动，直到用户催"怎么要这么久"。据此把插件重做成 `dsh-exploration-guard`：以 agent-loop 的 **step** 计数，以**任务节点推进**（todo 完成数增量 / goal 终结 / 新建 goal）为唯一进展信号，两档熔断（先否决非进度工具，再只留记录/求助），全部在 `tools.guard` 内完成，不注入消息、不占用户发言位。

## 0. 结论

1. **改名并重建**：`nfm-exploration-guard`（同参数判据）已卸载删除；新件 `dsh-exploration-guard@0.2.0` 已装（applied），判据是**任务进展**不是调用重复。
2. **"无进展"的定义**：距上次任务节点推进已经过 N 个 step。推进只认三件事——`todo_write` 的 `completed` 计数增加（首次建表也算）、`update_goal` 的 `action` 为 `complete`/`blocked`、`create_goal`。**原样重写任务表不算**。
3. **两档被动约束**（soft=15 / hard=25，可配）：soft 起否决所有非进度工具，理由本身就是提醒；hard 起只放行 `todo_write`/`get_goal`/`create_goal`/`update_goal`/`ask_user_question`/`meta_route`/`meta_sign`，其余一律否决并要求 Owner 授权。
4. **不占发言位**：全部通过 `ctx.tools.guard()` 返回否决理由实现，不往消息流里塞任何 user/context 消息；不碰 `llm/stream`。
5. **例外**：agent 进入 `idle`（等 Owner 发言）时计数清零；无任务清单默认同样计时（`noTaskMode: 'count'`），可改 `'skip'`。

## 1. 判据为什么换

| 判据 | 抓得到 | 抓不到 |
|---|---|---|
| 同参数连续调用（v0.1） | 原地重试同一命令 | **探索黑洞**：每次换参数、换假设、换工具，任务却不推进 |
| 推理重复（loop-guard） | 只想不做的空转、短语池轮转 | 有实际工具产出但方向漂移 |
| **任务进展（v0.2）** | 一连串"有产出"的调用却没落到任务节点上 | 任务节点本身定义错（todo 写得烂）的情况 |

真实轨迹特征（Owner 提供）：一步里连续 `find` → `read` → `write 临时脚本` → 跑 → 失败 → 换思路 → 再找；中间还有一次退出码 1 的搜索、一次引号事故后改写脚本、一次 asar 头部偏移算错重来。这些都是**探索成本**，不是**任务进展**。

## 2. 机制

- **计数**：`ctx.on('agent/pre-step')` 每次 +1（agent-loop 的 step，不是 turn）。
- **进展**：guard 在调用前读参数判定（不需要等结果）：
  - `todo_write`：`completed` 计数比上次大 → 进展；首次建表 → 进展（否则开局就被拦）；列表原样重写 → **不算**。
  - `update_goal`：`action ∈ {complete, blocked}` → 进展。
  - `create_goal` → 进展。
- **熔断**：`since = steps - lastProgress`；`since ≥ softSteps` 时否决非 `allowAlways` 工具；`since ≥ hardSteps` 时文案升级为"需要 Owner 授权"。
- **状态隔离**：`WeakMap<agent, state>`；切换 session 才重置，**首次绑定 session 不重置**（见 §4）。

**文案语言（Owner 2026-10-28 裁定）**：Loops 侧按惯例**只用英文**，否决理由不随界面语言切换；双语只留在设置面板。

- soft：`No task progress for {steps} steps (soft={soft}). Advance the task before continuing: …`
- hard：`No task progress for {steps} steps: tool calls are temporarily blocked (hard={hard}). You may only update the task list or goal, or ask the Owner for authorization. Do not start new investigations.`
- 实机验证：把阈值临时改成 soft=1/hard=2 后，两档英文文案各命中一次；随后恢复 15/25（`config.json` 内容 `{"softSteps":15,"hardSteps":25}`）。
- 副作用观察：被 hard 拦住时，`pwsh` 走 HTTP 恢复也被拦（它也是工具调用）；**唯一出路是让 `completed` 数增加**（原样重写任务表不算）或 `update_goal` 走到终态。同一步内先 `todo_write` 再发别的调用会被放行（`since = 0`），这是"记完就干"的通道。

## 3.1 设置界面（v0.3.0）

Owner 指出"数值要能在通用设置里改"，本轮补上：

- **宿主侧**：`inject = ['tools', 'webServer']`，`ctx.webServer.register({kind:'prefix', path:'/exploration-guard', handler})` 提供 `GET/POST /exploration-guard/api/config`；值落 `$DSH_HOME/exploration-guard/config.json`，**文件值覆盖 patch 初始 config**，POST 后守卫即时读到新值（同一份可变 cfg）。
- **客户端**：`dsh.client`（web）+ `./client` 导出，手写 `window.__ModuleLoader__.load` 模块，注册到 `settings.section`（order 640，zh/en 双语文案），五个控件：启用、软阈值、硬阈值、无任务清单口径、等待 Owner 清零。
- **实测**：`GET` → 200 返回当前值；`POST {"softSteps":18}` → `applied` 且回读为 18；恢复 15 后文件内容为 `{"softSteps": 15}`。宿主 API 是端到端验证过的；**面板渲染未肉眼验收**（需要刷新页面加载新客户端模块）。
- **重装注意**：link 安装的包改了 manifest（新增 client 声明）必须 `remove_bundle` → `install_bundle`，只调 `install_bundle` 会返回 `already-installed`，旧模块代不会刷新。

## 3.2 存储与路径隐私（Owner 2026-10-28 追问后修）

Owner 看到面板上显示 `C:\Users\<用户>\.dsh\exploration-guard\config.json`，问编码与路径泄露。

- **文件编码**：`JSON.stringify(values, null, 2)` + `fs.writeFileSync(..., 'utf8')` → **UTF-8 无 BOM**、纯 ASCII、两空格缩进，实测 40 字节；内容只是改过的键（`{"softSteps":15,"hardSteps":25}`），**不含路径、时间戳、会话 id、用户名**。
- **确认过的泄露点**：不是文件，而是 **API 响应 / 面板页脚**——`GET` 原样回传 `configFile()` 的绝对路径，客户端直接打印。这条已改：响应返回符号路径 `$DSH_HOME/exploration-guard/config.json`。
- **顺带堵住第二条**：异常分支原来回 `String(error.message)`，fs 错误正文里带绝对路径 → 改为泛化文案 `settings request failed`，详情只进宿主日志。
- **回归**：夹具断言响应不含测试 home 目录、也不含 `Users`；实机 `GET` 复核 `hasAbsPath false`，畸形 body 返回 `200 {applied:{}}` 不抛错。
- **残留风险**（如实记）：宿主日志（`console.warn`）仍会记录绝对路径；文件 ACL 是 Windows 默认（SYSTEM / Administrators / 当前用户），同机其它用户读不到，但没有做额外的 0600 式收紧。

## 4. 实现里踩到的坑（已修，夹具覆盖）

**首次绑定 session 不能清基线**：guard 可能在第一个 `pre-step` 之前就被调用（模型先调 `todo_write`），此时 `state.sessionId` 还是 `undefined`；若把"sessionId 从 undefined 变成 s1"当成切换会话去重置，刚记下的任务基线会被抹掉，紧接着的第一次 `todo_write` 又被判成"首次建表 = 进展"，等于永久免检。修法：`undefined → id` 只登记身份，只有 `id → 另一个 id` 才重置。

## 5. 未决与未验证

1. **soft=15 / hard=25 是拍的**：没有真实长任务分布支撑，需要跑几轮看误伤率再定；`enabled: false` 是整机开关。
2. **goal 自动推进的口径未定**：如果 goal 引擎在每个 step 自动推进轮数、但模型不调 `update_goal`，本守卫仍按"无进展"计时，可能在合法长任务里误伤。Owner 的例外清单里提到"通过 goal 自动推进轮数"，这一支我**没有实现**自动豁免——需要确认 goal 推进是否伴随工具调用，再决定接哪个事件。
3. **"等待 Owner 发言"**：目前靠 `agent/status = idle` 清零覆盖；如果某些等待场景不进 idle（例如 job 轮询），会继续计时。
4. 与 `dsh-loop-guard` 的交互未测：两者都可能导致"回合结束"，计数是否会在切断后重置取决于是否经过 `agent/status`。
5. 未在真实探索黑洞会话上回放（没有现成录音），只做了夹具。

## 6. 适用边界（Owner 2026-10-28 纠正后补记）

**本守卫的目标是"能正常调工具、但方向漂移"的模型（DeepSeek 一类高质模型），不是"思考内死锁"的低质模型。**

判据依赖工具调用：要走 `tools.guard` 才能拦，要被 `todo_write` 之类的进度调用才能清零。GLM 4.6V 的失败形态是**推理阶段死锁**——它想调工具但思考在循环里出不来，工具面根本没有请求到达。所以：

- 那类会话里本守卫**理应 0 触发**，不是判据失效，是判据的射程之外。
- 同一会话里 `dsh-loop-guard` 响了 26 次（`已连续重复` 注入 26 次）、仍未能让模型停下：切断只能限幅，不能教会模型收尾。**据此 Owner 于 2026-10-28 判定它冗余并卸载**（`remove_bundle @mrweicodes/dsh-loop-guard`，profile 已无该行、node_modules 已清）。
- 按回合（`agent/status = idle`）清零是 Owner 定的口径（"等 Owner 发言"算例外），不是缺陷；跨回合累计会让正常的"一问一答"被误判。

**实测（目标场景）**：本会话施工期间命中 2 次——15 步无任务进展时 soft 档拦下一次 `read`、hard 档拦下一次 `pwsh`，两次都是英文文案，模型（DeepSeek）读到理由后先 `todo_write` 记进展再继续。这就是它该有的样子。

## 7. 受限期文案契约（Owner 2026-10-28）

实测教训：模型被拦后**重写同一张 todo 清单**（`completed` 没增加）然后继续尝试，于是被连拦十几次，还看懂了"只能改清单"却不懂"改了不算"。所以文案改成两句话回答清楚：

- **无用**：重写清单（`completed` 不增加不算进展）、继续读/写/跑 shell；
- **有用**：把**真正做完**的事标 completed、`update_goal` blocked、问 Owner；
- **禁止**：为了让拦截放过而假标完成（Owner 2026-10-28 指出：守卫不能教模型违背事实地标记完成）——hard 文案明写 `never mark work complete just to unblock`；
- **锚点**：带 `step(s)` 与 `completed=N`，模型自己就能算差多少。

```
soft: Blocked: {steps} step(s) since the last completed todo (soft={soft}, completed={done}). Rewriting the list does not count. Honest ways out: mark a genuinely finished item completed, update_goal blocked, or ask the Owner. Other tools are refused.
hard: Blocked: {steps} step(s) (hard={hard}, completed={done}). Only honest progress passes: mark a genuinely finished item completed, update_goal blocked, or ask the Owner — never mark work complete just to unblock. Everything else is refused.
```

实机复测：`softSteps=1` 时 soft 档与 hard 档各自返回上述文案，随后恢复 15/25；夹具 9/9（新增断言：含 `completed=`、明确"重写不算"、明确"其它工具被拒"、长度 < 400）。
