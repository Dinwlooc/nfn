# 0020 插件市场换装：装两块测量面，退役一块重叠件（2026-10-27）

keywords: 插件市场,换装,dsh-context,dsh-usage,版本体检,回滚,plugin-manager

**摘要**：把 profile 的市场索引合并成可检索的统一目录（3,909 个唯一插件），逐一做了版本体检与候选比对；结论是自造轮子（meta-tools / project_files / budget-watch / godot-creator）没有 drop-in 替代，市场真正强的是"测量与展示"面。据此装 `dsh-context`（上下文/成本归因）与 `@linxin666/dsh-usage`（余额与用量账本），并把功能重叠的 `dsh-context-lens` 退役；`dsh-kimi-subscription` 顺升 1.4.0。执行中 `plugin_manager` 被 Auto review 预设拒单，改用官方 CLI 通道完成。

## 0. 结论

1. **自造轮子无可替换项**：`dsh-meta-tools`（元层路由/签发）、`project_files`（Godot 类型检索 + 回收站删除）、`dsh-budget-watch`（项目预算口径）、`godot-creator-ui`（MCP 状态与 usage_report）在 3,909 个插件里都没有对应物——它们是项目特化件，不是通用轮子的重复实现。
2. **真正的重叠只有测量面**：`dsh-context-lens`（请求差异 + 缓存复用告警）与 `dsh-context`（上下文构成、缓存命中、每请求成本、工具 schema 来源、File Activity、`/context` 命令）重叠，后者严格更强，故**退役 lens、装 context**。
3. **新增两块测量面**：`dsh-context@0.77.0`（applied 即时生效）、`@linxin666/dsh-usage@0.4.8`（余额/套餐额度 + 实时用量账本）。
4. **版本体检**：除 `dsh-kimi-subscription` 1.3.8→1.4.0（已升，且它只是依赖、未挂 bundle）外，其余社区插件均为当日最新；npm 显示 market-bundle 的 `latest` 为 0.2.1-alpha.4，低于已装 rc.3，**不降级**。
5. **通道事故**：Owner 切到 Auto review 预设后，`plugin_manager` 全部调用被 `auto-review: the pending root call is missing or ambiguous in the session log` 拒单；改走 `dsh plugin --profile desktop <pnpm args>` 完成后续变更（官方 CLI，不是手改 profile）。

## 3. 装什么 / 不装什么

**装**
- `dsh-context@0.77.0`（★3,662，verified）：上下文构成、缓存命中、每请求 token/成本、工具 schema 来源与体积。这是把"省 token 的猜测"变成可读数的最短路径，也是 0015/0016 缺的那块仪表盘。
- `@linxin666/dsh-usage@0.4.8`（★9,612）：provider 余额与套餐额度 + 实时用量账本。用于把 ¥ 预算可视化，与 `budget-watch`（模型面记账）互补而非冲突。

**不装（有证据的决定）**
- `dsh-plugin`（★365）/ `dshmarket`（★9,139）：都是 Web UI 市场，与已装的官方 Discover（`plugin-market-bundle`）功能重复；拆包确认其 lib 只有 http/services/client，**不提供模型面工具**，替代不了检索脚本。
- `dsh-code-index@0.11.1`：机制对口（tree-sitter 影响面分析），但 0014 判定为 C 级证据、市场 star 为 0，且首次索引成本未知；留给"有时间做 A/B"的一轮。
- `billion-context`（★3k）/ `@zoria-lind/dsh-token-optimizer`：一个替换压缩、一个叠加裁剪/缓存/懒 MCP，均与现有 save-token + tool-search 的已验证配置重叠，收益未证、回滚面大。
- `dsh-cost-meter`（★544）：与 `budget-watch` 的账本口径冲突（本项目按 billed+quota 原始 token 与 Owner 发放量比较），换掉等于改预算协议 → 不动。
- 官方 `@deepseek-ai/dsh-experimental-session-search`：装后要求重启（`package-moved`），且它的 `session-query-sqlite` 行与 base 已有同名服务行重复，重启有重复注册风险；收益（跨会话检索）不抵风险 → 装后即卸、依赖也清掉。

## 5. 自造轮子判定（为什么不换）

| 自造件 | 市场候选 | 判定 |
|---|---|---|
| `dsh-meta-tools`（route/sign/tasktype/theme） | 无（memory 类如 dsh-mnemon / engramory 是长时记忆，语义不同） | 保留：这是本库路由协议本身 |
| `project_files`（类型检索 + 回收站删除） | 无（trash 类只删会话） | 保留：Godot 噪声过滤 + 引用拦截无替代 |
| `dsh-budget-watch` | dsh-cost-meter / dsh-usage-stats | 保留：项目预算口径唯一实现；展示层已外包给 dsh-usage |
| `godot-creator-ui`（状态芯片 + usage_report） | 无 | 保留：MCP 状态与模型面计量 |
| `custom_tools/audit/*`（4 个缓存审计脚本） | dsh-context（实时看板） | 保留：审计是历史回放，看板是实时观测，互补 |
| `dsh-context-lens` | dsh-context | **替换**（本次唯一换装） |

## 7. 验证缺口（未验收项）

- `dsh-context` / `dsh-usage` 的**浏览器面板**要刷新后才出现；本轮只验证到"包在盘上、bundle 在清单里、plugin_manager 报 applied"，**没有肉眼验收 UI**。
- `dsh-usage` 的余额探测依赖 provider 账户路由，是否能在 deepseek-account 下取到余额未验证。
- 未做 A/B：本轮不动模型调用路径，token 影响只来自新增 UI 行（无模型面 schema），预期为 0。

## 8. 教训

1. **Auto review 预设会让 `plugin_manager` 整体不可用**，报错 `pending root call is missing or ambiguous in the session log`；这不是权限拒绝，是 reviewer 的会话日志找不到待审调用。应急通道 = `dsh plugin --profile desktop <pnpm args>`（官方 CLI，改的是同一份 profile）。
2. **官方 experimental bundle 装进去就拔不出来**（`not-removable`），只能 disable；装官方实验件前先看它的行是否与 base 已有服务重名。
3. pnpm 的 `Packages: +1 -8` 是修剪噪声，不代表删了业务依赖——以最终 `package.json` 为准。
4. 市场索引的版本会滞后于 pnpm 解析结果（dsh-usage 0.4.11 vs 0.4.8），**两者不同时以实际落到盘上的为准**，并在论文里记下差异。
