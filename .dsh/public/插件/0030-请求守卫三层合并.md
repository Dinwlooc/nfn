# 0030 请求守卫：三层合并（写入 / 请求 / 错误）

keywords: 请求守卫,request-guard,空id,tool-call,邻接,healer,退役,三层,可观测

**摘要**：GLM 4.6V 再次把会话玩崩（`session-f74352ed`：seq 303 的 tool-call `id`/`name` 双空、seq 304 的 `tool/call` 同样双空，其后日志直接断掉）。复盘证明 **healer 修的是请求层，救不了写入层**——脏块在它看到之前就已经落盘并被 agent-loop 当成待执行调用。于是按 Owner 裁定把优点合并成一件 `dsh-request-guard`：A 写入层补 id、B 请求层修消息数组、C 错误层重试一次；装它之后卸 healer、撤版本豁免。纯函数回归 10/10，stats 端点实机 200。

## 1. 这次崩盘的原始行

```
302 step/start
303 assistant/message   blocks = text | tool-call(id:"", name:"")
304 tool/call           callId="", name=""
    —— 没有 tool/result，没有 step/end，没有 turn/end
```

写入路径在生产 `tool/result` 时被会话格式校验拒绝（空 `toolCallId`），这一轮连收尾都没落盘；恢复时又从同一条 assistant 消息发现"待执行调用"——**结构性永久卡死**，与 0026/0028 同一病根。

已修：删脏块 + 配对 tool/call（306→305 行，留 `.bak`），全库复扫 245 会话 / 0 残留。

## 2. 为什么 healer 挡不住

| | healer | 事故实际发生的位置 |
|---|---|---|
| 时机 | 请求发出前 / 400 之后 | **更早**：流式输出落盘 + 工具派发 |
| 手段 | 给 `LlmRuntime` 原型打补丁，替换 messages | 空 id 已经被写进 `tool/call` |

层级不对，规则再对题也管不到。它还有两个代价：锁 `@deepseek-ai/dsh-llm 0.2.0-rc.2`（我们是 `0.2.1-rc.3`，只能靠精确版本豁免装）、以及和 `dsh-session-repair` 的语义重叠。

## 3. 三层设计

| 层 | 挂载 | 规则 | 解决 |
|---|---|---|---|
| **A 写入** | `llm/stream` 瀑布 | 空 `id` → 本流稳定的合成 id（同 index 复用） | 回合能收尾，会话不死 |
| **B 请求** | 包装运行中的 `llm` 服务实例的 `stream()` | R1 剔空 name 调用；R2 剔孤儿结果；R3 丢结果的调用补合成错误结果；R4 剔重复/错位结果；R5 非对象 `arguments` → `{}` | **已中毒的历史也能再发出去** |
| **C 错误** | `agent/request-error` 瀑布 | 配对/邻接类 `INVALID_REQUEST` → 重试一次（每回合上限可配） | 给 B 一个生效机会 |

**B 为什么不用公开钩子**：`dsh-agent-loop` 对派生消息与 options 做了 `deepFreeze` / `Object.freeze`，`llm/stream` 监听器只能读。包装**服务实例**的方法可以给适配器一个新 options 对象——比解析模块打补丁更稳，且**不锁任何 dsh-llm 版本**。

失败姿态一律 fail-open：修复抛错就原样透传，B 拿不到 `llm` 服务只记 `lastError`，A 层照常。

## 4. 验证

- 纯函数回归：`RESULT run.mjs: pass=10 fail=0`（干净历史零改动且同数组身份、R1–R5 各一、只剩空 name 调用的 assistant 整条移除、混合结果只留存活块、A 层 id 稳定复用且不覆盖真实 id）。
- 实机：`GET /request-guard/api/stats` → 200，`streams` 随请求递增，`lastError: null`。
- 装配终态（profile bundles）：`dsh-request-guard` + `dsh-session-repair` + `dsh-exploration-guard`；`dsh-healer` 已卸载、豁免已撤销，`dsh-stream-sanitizer` 已卸载（目录保留扫描/修复脚本）。

## 5. 边界（如实记）

1. **未在真实畸形流上复现验证**：今天没有 provider 再发空 id，A 层只有夹具证据 + 历史事故的回放式推理。
2. B 层依赖 `llm` 服务实例存在；服务形态若变，B 自动降级为 A（有 `lastError` 可查）。
3. C 层重试只对"配对/邻接类"文案生效；其它 400 不重试，避免把真实错误重放一遍。
4. 邻接规则按 DSH 原生消息（`role: toolResult`）实现，不涉及各 provider 的 wire 格式转换。
