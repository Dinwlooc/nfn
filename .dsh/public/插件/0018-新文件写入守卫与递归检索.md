# 0018 - meta-tools 新文件写入守卫与递归检索

keywords: meta-tools,写入守卫,realpath,递归检索,junction,投影单元,Standard Schema,读账

**摘要**：三条落地教训（新文件 realpath 守卫沿 dirname 上溯、检索必须递归、Windows junction 测试清理）+ 安装期五条 harness 协议硬事实（Standard Schema、content 数组、链接安装热生效、PATH 无 pwsh、projection 双 schema）+ 写护栏改为会话级原生读账（NOT_READ/STALE）。


任务：dsh-meta-tools 插件 v1 落地验证（glm L + deepseek H，OL1H）。三条可复用教训：

1. **新建文件的 realpath 守卫缺口**：confine 类检查只对"已存在目标"做 realpath；写新文件时父目录不存在，`realpath(dirname)` 直接 ENOENT。正确形态是**沿 dirname 上溯到最近存在祖先做逃逸检查**——不存在的词法段由词法 confinement 覆盖（那里不可能藏 symlink），mkdir 之后创建的是真实目录。祖先上溯到库根本身仍 ENOENT 时直接放行（词法已保证在库内），否则 `scaffold: off` + 全新工作区会被误报 IO_ERROR。
2. **检索必须递归**：元层库正文天然分布在不同深度（`public/<任务类型>/`、`<系>/<模型>/<任务类型>/`），按目录一层扫必然漏。递归遍历记得跳 `.tmp` 与 `*.revlog.md`。Dirent 的 isDirectory/isFile 对 symlink 返回 false，递归天然不跟随链接、不进环。
3. **Windows junction 与测试清理**：junction 无需管理员即可创建，适合在测试里验证"符号链接逃逸被拒"。但 Node `rm(recursive)` 会试图跟随 junction 导致 ENOTEMPTY——清理前先对 junction 单独 `rmdirSync`。

验证：`node .dsh/meta-tools/plugin/test/run.mjs` → pass=14 fail=0（修复前 4 失败）；H 复审结论 pass（confinement sound、runSearch sound），H 指出的缺根误报、静态导入、注释元数据三项均已落实。

**安装期补遗（同日，Owner"落成可用 DSH 插件"裁定后实测）**：四条 harness 插件协议硬事实，全部有报错/源码证据：
1. 加载器对 Config 走 **Standard Schema 协议**（`Config['~standard'].validate`，cordis fiber.ts resolveConfig）——手搓 `{validate}` 对象没有 `~standard` 品牌即崩"reading 'validate'"；不想引 schemastery 就**干脆不导出 Config**（对齐 godot-creator 形态），apply 内 normalize。
2. 工具 `output.render` 必须返回 **content 数组**（`[{type:'text',text}]`）——返回字符串则结果整形处 `content.some is not a function`（dsh-tools lib/index.js:1454 证实）。
3. 链接安装的包**换内容即生效**（remove+install 后新模块代被重读），不必重启；每次改动走一次 remove+install 即可。
4. 宿主进程 PATH 里没有 pwsh——spawn 外部命令要做 `powershell.exe` 兜底。另有教训：route.js 引用了未导入的 readFileText，`node --check` 查不出（运行期才炸），工具 execute 必须有单测覆盖。
5. **注册 projection 单元必须同时给 `stateSchema` 与 `wire.viewSchema`**（都只要求 `.parse`）：恢复会话时注册表两处都调 parse（dsh-session-projection lib/index.js:296/:304），缺任一即"历史加载失败 …reading 'parse'"，gateway/internal 级、挡住整个会话历史。zod 在 link 安装的包里不可解析，手搓 `{parse(v)}` 即满足契约（zod 形态参照 dsh-context-lens / dsh-goal）。另按 Owner 裁定：「每轮」是 Loops 的 turn 不是工具调用轮——工具内部不做登记，登记挂 `turn/end` 钩子。
6. **schemastery `.volatile()` 字段传给 apply 的是冻结的活引用格**（cosmokit `createVolatile` 的 `{get(){},[write]}`），JSON 序列化成 `{}` 是正常现象；每次消费都 `.get()`，勿在 apply 时快照。改值用 `updateVolatile(cell, createVolatile(value))`——**第二参是源格不是裸值**（cosmokit lib/index.js:150 `source.get()`）。Settings 改 volatile 值就是 loader 对同一格原地 updateVolatile，插件无需订阅。UI 面板的已验证通道：宿主 `webServer.register` HTTP 路由 + client 轮询（godot-creator-ui 形态，`settings.general.item` 槽位）。
7. **写护栏从哈希外置改为原生读账**（Owner 裁定 2026-10-27，H 第 8 轮设计）：会话级 `Map<sessionId, Map<abs, sha256>>`——read（仅正文读，revlog 读不记）与 meta_route 返回的未裁剪正文都记账；写已有文件无账 → `NOT_READ`，盘上哈希≠账面 → `STALE`；写成功即刷新账（连续编辑不误伤），delete 清账，session/disposed 清整个会话，插件卸载清全部。`hash`/`force` 参数从 schema 删除（模型不带任何令牌；force 可被模型自设，等于没守）。写走 tmp+rename 原子化缩小 TOCTOU。registry.json 语义 = 模型来访登记（models 行按会话 upsert；inventory 首跳回填）。
最终实测闭环：inventory → routing（模型自动识别）→ write(+revlog) → read(revlog) → delete（正文+日志同入回收站、事后 stat 验证）全部通过；库根按会话工作目录解析（workingDirectory 服务，cfg.root 可覆盖）。回归 pass=17。主题预设（theme→taskTypes）只在无 `.dsh` 的工作区自动应用生成文件（Owner 裁定 2026-10-26）；已有库只采纳 public/ 子目录、不重构。
