# 架构指标定义与评估框架

keywords: 架构指标,IMLAS,ISO25010,MOOD,CK,DSM,Martin,原子度,叶子判据,口径,oracle

**本文件只定"用哪套框架、怎么算"**：六族框架的层次归属、以方法为分母的 9 项形态指标公式、`@atomic` 的叶子判据、7 类台账的判定优先级、以及证明"只改注释"的三个 oracle。**实测数字见 `0009`，判读与主张见 `0010`。**

基线：2124597+WIP（2026-10-25）

## 一、先定层次：六族框架各量在哪一层

自创指标贴合项目但缺外部基准。选型的核心判据不是"哪个指标好"，而是**它坐在哪一层**——不同层的指标不能放进同一百分制。

| 框架族 | 代表指标 | 量化对象 |
|---|---|---|
| CK | WMC、DIT、NOC、CBO、RFC、LCOM | 类的复杂度、继承、耦合、内聚 |
| MOOD | POF、AC、EC、IS、CoC、DC、FA | 面向对象机制的使用强度 |
| QMOOD | 11 项设计度量 → 6 项质量属性 | 设计度量到质量属性的加权映射 |
| Martin 主序列 | Ca、Ce、I = Ce/(Ca+Ce)、A、D = \|A+I−1\| | 层级的稳定性与抽象度是否匹配 |
| DSM / 传播成本 | 依赖矩阵、传递闭包密度 | 整体结构耦合的传播与演化成本 |
| ISO/IEC 25010 | 模块性、可复用性、可分析性、可修改性、可测试性 | 质量属性术语与测量框架 |

**层次划分**：L1 源码形态（WMC、原子度、叶子率）／L2 类间关系（CBO、LCOM、DIT、MOOD AC/CoC）／L3 包结构（DSM 传播成本、Ca/Ce/I/A/D）／L4 演化（共变模块度、变更传播）／L5 质量属性与意图（QMOOD 6 属性、ISO 25010、范式台账）。

## 二、选定的框架：IMLAS 四层

| 层 | 采用 | 本项目实现 |
|---|---|---|
| L5 术语层 | ISO 25010 可维护性五子特性 | 对外汇报一律换算到此，不新造术语 |
| L4 意图层 | 无标准对应 | 项目范式台账（`@atomic`/`@delegates`/`@pure`…），**标注为非标准** |
| L3 结构层 | DSM 传播成本 + Martin Ca/Ce/I/A/D | `_tool_arch_deps.py` |
| L2 关系层 | CBO + LCOM + DIT | 同上 |
| L1 形态层 | WMC 粒度 + 原子度 + 参数均 + 叶子率 | `_tool_arch_scan.py` + `_tool_arch_report.py` |

**纪律**：分层汇报、禁止跨层加总；自创指标只作内部仪表，对外一律换算到 ISO 25010。

## 三、分母与口径（决定一切读数）

- **分母 = 非生命周期方法数**：排除 `_init`/`_ready`/`_process` 等生命周期钩子后的方法数。换分母的读数不可比。
- **成员作用域**：只认类体缩进层级的 `var`/`const`；方法内局部变量不算成员（这条曾出过实现 bug，v1.2 修正）。
- **静态方法**：无实例状态，恒计入安全性；但"是否原子"由**叶子形式**决定，不由 `static` 推出（v1.2 前提作废后的结论）。

## 四、形态指标公式（与 `_tool_arch_report.py` 的 `agg()` 逐条一致）

记 `n` 为非生命周期方法数，`static`/`private`/`leaf` 为对应计数：

| 指标 | 公式 | 读法 |
|---|---|---|
| 静态率 | `static / n` | 无实例状态的比例 |
| 叶子率 | `leaf / n` | 方法体不调用本文件内其他方法（可调引擎 API 与外部依赖） |
| 封装度 | `private / n` | 私有方法占比 |
| 安全性 | `(static + 非静态且 kind ∈ {pure, safe_inst, read}) / n` | 静态 + 只读 + 纯函数 + 外生 的合计占比 |
| 风险率 | `kind ∈ RISK 的计数 / n` | 未标注且按方法体确认写了自身或入参 |
| 完整度 | `1 − (risk + un_call) / n` | 既没写状态、也不是"只调用"的比例 |
| 复用密度 | `导出计数 / n`，导出 = `(static 且非 private) + (非 static 且非 private 且 pure)` | 可被外部复用的方法占比 |
| 原子度 | `Σbranches / n` | 平均分支数（分支越多越不原子） |
| 参数均 | `Σparams / n` | 平均参数个数 |

类级与结构级指标（由 `_tool_arch_deps.py` 产出）：

- **LCOM（CK 口径）**：不共享成员的方法对减去共享对数，负值按 0 计；**仅对实体类且方法数 ≥5 有效**（数据类无状态可共享，读数无意义）。
- **Ca / Ce / I / A / D**：Martin 主序列；`I = Ce/(Ca+Ce)`，`D = |A+I−1|`。
- **传播成本**：静态可达对数 / `N(N-1)`，是**上界近似**，不是真实变更传播（后者需 git 历史）。

## 五、依赖图三口径（环的读数必须标口径）

| 口径 | 边怎么取 | 用途 |
|---|---|---|
| 类型声明网 | 类型标注、常量与静态引用、签名参数、`is` 判断 | 结构性耦合的**上界** |
| 调用网 | `extends` + 静态调用 + 实例化 | 真实可执行依赖 |
| 调用网 v2 | 调用网 + 按声明类型推断的实例方法调用 | 接近实际运行路径 |

**纪律**：报"环化率"必须同时报口径；不同口径的环数不可比。`_tool_arch_deps.py` 输出的是**类型声明网**；调用网需另跑 `_tool_arch_callgraph.py`。

## 六、`@atomic` 判据（owner 定义）

- `@atomic` = **叶子方法形式**：方法体不调用本文件内其他方法。
- 允许标注的情形：原子业务步骤（一次状态变更或一次转发）。
- 越标（`@atomic` 但非叶子）视为**错误标注**，须清零；`_tool_arch_report.py` 表 4 直接给"叶子 / 非叶子"计数。

## 七、7 类台账的判定优先级

同一方法可能同时满足多个标签，按下列顺序只取一个（先命中先得）：

1. 未标·改自身+参数 → 2. 未标·改参数 → 3. 未标·改自身 → 4. 未标·仅调用 → 5. 未标·无写入 → 6. 静态·未标 → 7. 已标注（`@hook/@override` → `@side_effect` → `@delegates` → `@atomic` → `@pure` → `@internal` → `@external` → `@factory` → `@facade` → `@operation`）。

判据要能被证伪：任何"已标注"的归类都必须有方法体证据（写了自身/写了入参/只调用/无写入）。

## 八、三个 oracle：证明"只改注释"

改动形状不能在数字上撒谎，用三条独立判据互相印证：

1. **形状雷达** `_tool_shape.py`：输出 `SAME` / `COMMENTS-ONLY` / `CODE-DIFF`（含暂存区）。
2. **计数不变**：`_tool_arch_scan.py` 前后 `files` / `methods` / `non_lifecycle` 三数不变。
3. **台账不变**：`_tool_arch_report.py` 表 5 各分类计数逐项不变（差值必须为 0）。

三者任一报变，就不能宣称"只改注释"；`CODE-DIFF` 与"计数不变"冲突时以雷达为准（它看字符级差异）。

## 九、口径与局限

1. 排除 `addons/`（第三方）与 `Unused/`（`.gitignore` 归档）。
2. 依赖网剥离注释与字符串后取边；类型标注也算依赖，故为**上界近似**。
3. LCOM 只在实体类上有效；层均值必须标支配者（例如 `System/Item` 由实体类支配）。
4. 传播成本是静态可达近似，不含真实变更频率。
5. 数字与工具输出对不上时**以工具输出为准**，差异要写理由（`0009` 就是这么重做的）。
