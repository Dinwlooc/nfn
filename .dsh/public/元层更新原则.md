# 元层更新原则

keywords: 元层更新,何时更新,层级归属,单一真值,印章,维护禁令,入口只留指针

## 何时更新

- 理解错误、选型失误、审验类任务的量化发现、算法任务完成后的征询。
- **不对未验证的结论做知识升级**；印象层只在实质位移时修订（轨迹一行）。

## 怎么更新（层级归属）

| 层 | 归属文件 | 谁能改 |
|---|---|---|
| 法 | `.dsh/NFN-AIGC规则-*.md` | 只属 owner |
| 细则 | `public/<类型>/细则.md` | 任何 AI，改动处署名 |
| 知识 | `public/<类型>/NNNN-*.md` | 任何 AI 交叉编修；改动后 `meta_sign` 签发 |
| 印象 / 环境经验 | 模型库 `<系>/<模型>/meta.md`（二级 meta） | 只属该模型 |
| 私人调优 | 模型库 `<系>/<模型>/<类型>/` 目录 | 只属该模型 |

## 维护禁令

- 写进他人文件的任何片段，写后立即 `meta_sign` 签发（印章是唯一署名入口）。
- 不用 Markdown 转义。反斜杠会写坏路径与字段名。
- **实验/测试记录不得写进入口与规则文件**（owner 裁定 2026-10-25）：route 名、报错原文、逐次对照、带日期的实测数据，一律写 `.dsh/experiments/`（记录）或唯一展开处（如 OL1H）；入口文件（`元层索引.md`、各类型 `细则.md`、`AGENTS.md`）只留一行指针。判据：一句话若"下个版本就会变"，写指针而不是事实。（deepseek-flash ｜2026-10-25，Owner 裁定：清算早期实验乱写）
- **每类规则只在一个文件展开，其余只留指针**：发现第二处展开就地改指针；指针必须指向展开处，不指向另一个指针；落笔后核对目标文件存在。（deepseek-flash ｜2026-10-25，Owner 裁定）
- **不写会漂移的事实**：版本号、未提交项数、当前策略一律用指针；**额度、模型/工具的可用性也是瞬态**——耗尽会恢复、开关会变，规则只列对象，写"用前现探"。（deepseek-flash ｜2026-10-25：把"glm 无额度"写进 H 候选表的教训）**统领性文件（细则、禁令、规则）还禁写具体实例作论据**——实例随时间失效或被推翻，条款应写成判据本身；需要实例时查 `.dsh/experiments/` 或各库记忆，不进条款。（glm-5.3-flash ｜2026-10-25，Owner 裁定：细则中写实例教训）
- **署名一律走印章**（Owner 裁定 2026-10-27）：作者、日期、改动内容只由 `meta_sign` 写入伴生 `.revlog.md`；正文不写署名、不写版号、不写修订记录段。知识库文档格式见 `public/README.md`。
- **统领性文件的排版随注意力规律维护**（Owner 裁定 2026-10-25）：硬约束置顶、解释居中、可执行清单置末；"不要 X"须配对正向"做 Y"且绝对禁止语义不软化；规则编号跨重排保持稳定；示例须显式构造完整内容，不引用项目文段。唯一豁免的重复冗余：超额即停、单文件探路两条不变量允许在首尾两处出现。

## 注意力规则

- **知识入库即移出会话上下文**，需要时再取；不在会话里复述已入库内容。
- 会话阶段（初期定工具 / 执行期不二次建议 / 收尾不扩任务）见 AGENTS.md。

## 结构

- **公共层与模型元层同构**：`public/<类型>/` ↔ 模型库 `<系>/<模型>/<类型>/`；公共层是模型层的扩展。
- **子文件夹是父文件夹的扩展**：越具体的层越深；更泛用的层放更上面。
- 模型库内部布局（二级 meta / meta/ 强加载方法 / 字符常量 / 记忆的职责划分）唯一展开处见 `.dsh/public/meta/元层索引.md`。

## 可发现性（路由的根本目标）

- **可发现性 = 新会话冷启动第一跳就能直接发现元层的价值**，不靠思考、探索与交叉验证补课。
- 元层设计产物（路由、索引、必读清单）以此为准绳：入口文件、密钥、身份、必读必须在路由输出里一次性给全；缺什么，弱 AI 就会在探索里烧 token。
- 判据：meta_route 两跳（无参清单 + taskType 必读）一屏给全身份、类型与必读；缺什么，模型就会在探索里烧 token。
- 实测教训（2026-10-25）：任务类型与协作类型解耦后，旧知识若与新维度不一致，会在冷启动时制造二次裁决——元层更新必须同步所有指针，不留旧口径。

## 可发现性（Owner 2026-10-25 定为路由的根本目标）

- 本节的判据：**入口文件、密钥、身份、必读，必须在路由输出里一次性给全**；缺什么，弱 AI 就会在探索里烧 token。
- 维护禁令排在注意力规则之前；指针条款要求"落笔后核对目标文件存在"。
- 统领性文件的排版：硬约束置顶、正向配对、编号稳定、给显式构造示例、例外条款冗余列出。
- 修订史折叠：修订条目超过 6 条时依次丢弃最早的，只留最近两条（`meta_sign` 的 revlog 保留条数即此规则的落地，见 `.dsh/meta/config.json`）。
