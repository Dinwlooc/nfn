# 插件类型 · 经验

均为本库成员实测后登记，含复现依据。

## 组合与插件教训

1. **cordis.patch.yml 的 `!!js` 只准用文档形态的 ctx 服务调用**（如 `dshHomePath('sessions')`、`!ctx.get(...)`）——它是 Loader 表达式方言，不是通用 JS，`process`/`env`/`cwd` 不可用。实测：在 `bundledSkillDir` 写 `!!js process.env...` 使 skill-filesystem 挂载抛错，preset 激活链下游全灭——症状看似多系统齐坏实为单一根因。改组合文件前先过 `cordis-composition-reference` 方言校验；没把握就保持字面量，功能优先、解耦另找受支持机制。
2. **profile 层与 bundle 层不得重复挂载同一服务**：`@deepseek-ai/dsh-subagent` 与 `subagent-model-selection-settings` 由 profile 层全局声明（含模型白名单），bundle patch 的 preset 里再插一份 → `service has been registered` 报错。
3. **测试 SKIP 不可当 PASS 看**：环境性 SKIP（沙箱禁 spawn、禁建符号链接）会掩盖真实缺陷。带 SKIP 的回归要在真实通道抽样验证至少一次。
4. **模型面说明不进 README**：插件 `README.md` 只给安装者读；模型可发现的通道只有预设注入（persona）与工具 description。
5. **插件层工具不进公共 `.dsh/custom_tools/README.md`**：后者只收可复制脚本工具；模型面分工经预设注入，插件行为说明在插件层 README（安装者），元层索引只留指针。
6. **注册表会话启动定型**：插件/工具实装后，本会话与既有会话都看不见，需重启会话；"tool_search 搜不到"要先查是不是时序问题，别急着改配置。
