# 对局打法与驱动（NFN）

keywords: 对局打法,渲染层索引,合法目标,结算规律,额度,AI决策,驱动,eval纪律,计时器

游戏侧操作知识：规则、AI 行为、驱动与读数。**牌面描述以 `resource/default/translations/cards.csv` 为准**（键 `<name>` 与 `<name>_DES`），不确定就读表，不猜。

## 一、读手牌必须走渲染层（最容易翻车）

逻辑顺序 ≠ 出牌下标。`c_play_selected_card(index, target)` 吃的是**渲染池下标**：

```
OperationManager.play_card_by_index() → hand_area.get_item_by_index(index) → items_pool[index]
```

实测对照：逻辑 `get_all_cards()` = `attack, repair, laser, shield, shield`，渲染池 = `0=attack, 1=laser, 2=shield, 3=shield, 4=repair`。按逻辑顺序算下标 → 打错牌 → 被拒（白丢一次响应权）。

```gdscript
var ra = scene.get_node("Control").render_context.get_render_area(&"hand")
for i in range(ra.get_item_count()):
    var pack = ra.get_item_by_index(i).data as CardPack   # id / name / type / player_id / get_card_type()
```

**一手全是同类牌时索引不会错，容易误判"这个写法已经验证过"。**

## 二、朝向与合法目标

| 牌 | `type` | 朝向 | 合法目标 |
|---|---|---|---|
| 交锋 | attack | `DEFENDER` | 其他玩家 |
| 激光 | attack | `DEFENDER` | 其他玩家（威力 0，靠【压制】） |
| 护盾 | defence | `ATTACKER` | 自己（`LIFE_DAMAGE_MODE = NONE`，不伤生命） |
| 修复 | spell | — | 任意玩家（治 4 生命 / 2 精神） |

报错对照：`不能对自己使用` = 攻击牌选自己；`不能对其他玩家使用` = 护盾选别人；`只能以当前守区拥有者为目标` = 目标必须是守区主。守区主看阶段标签 `DefenseBattle [Px]`。

## 三、结算规律

- **规则取自守区顶牌的 `settle_card`**：顶牌是交锋 → 对 DEFENDER 造成生命伤害；顶牌是护盾 → `LIFE_DAMAGE_MODE = NONE`，只削 ATTACKER 精神。
- **斗牌成立**：守区顶两张必须**分属不同玩家**（`check_battle_formation`）；单张牌不构成斗牌。
- 取胜路径：我的交锋压进敌方守区 → 对方接牌抢顶 → 用激光【压制】炸掉压在上面的牌（压制条件：`is_suppressing()` 且 `BattleCommand.Context.phase == PRE_DUEL` 且 `top_card` 是激光）→ 我的交锋裸露为顶牌 → 对方放弃响应 → 结算 → 扣血。
- **交锋结算后回手**（【结算】使此牌移入攻方手牌），可反复用。
- **拿不到顶牌就是白出牌**：顶牌是护盾时双方都不掉血，只削攻方精神。

## 四、额度：`settle_count >= speed`

- `speed` 在 `PlayerData`（默认 1），**`Player.get("speed")` 取不到**。
- 拒绝报错：`主阶段：守区结算次数已达攻击者速度上限`。
- 额度记在**被攻击方守区**上，不是"我出了几次牌"；`reset_settle_count()` 只在**主阶段结束**触发。
- 含义：同一主阶段里，某守区结算过一次就不能再往里压牌；但守区攻防期间可连续抢顶。
- 例：兴奋剂「仅限自身，失 1 精神，恢复 1 行动点，本回合速度+1」可直接突破该上限。

## 五、对手 AI 的决策机与弱点

弃牌阶段无条件放弃。主阶段：①守区空且手里防御牌 >1 → 随机防御牌打自己；②本回合没攻击过且有攻击牌 → 找 `settle_count < speed` 的玩家，随机攻击牌打过去；③否则放弃。守区攻防：非响应者放弃；守区主找防御牌打自己；攻方找攻击牌/技能打守区主。

弱点：**不会用修复**（只认 ATTACK/DEFENCE，spell 直接 pass）；只在守区空时铺防；每回合只攻一次；不会为抢顶连续压牌。**真人不会这样，别套用 AI 节奏。**

## 六、状态读数探针

```gdscript
var gs = scene.get_node("System").game_state
# 玩家：gs.player_manager.get_player_by_id(pid) → HP/MP/AP/morale_*
# 守区：gs.area_registry.get_defense_area(pid) → get_all_cards()/get_top_card()/get_second_card()/settle_count
# 手牌：见第一节（必须渲染层）
```

- 顶牌用 `get_top_card()`，**不要按 list 位置推断**。
- 别读 `HPBar/FillBackground` 的 `visible`（恒 true，只改颜色）；读 `Player.HP` 或 `$HPBar/ValueLabel.text`。
- 阶段标签会滞后（`StageFace` 有动画队列），判断"现在能不能出牌"用 `AP`、守区内容、`settle_count` 交叉验证。
- 控制台缓存上限 100 行，会顶掉早期日志。

## 七、牌库与配置

`cards_load_list.cfg` 决定每牌张数（倍数），`CardsManager.load_all_cards()` 再为每张配 4 个花色：`attack 2 / laser 1 / shield 2 / repair 1` → `6×4 = 24` 张。翻译表里还有 20+ 张未启用的牌（`burn_*` 燃烧系、`gun_*` 枪械系、迫击/城墙/轰炸等）。

## 八、驱动与 eval 纪律

- 进牌桌两条路：菜单 `ItemList_TestGame`（只能按坐标点，约 `(1460,260)`，窗口 1600×900）或更稳的 `project_run(mode="custom", scene="res://core/tscn/game/main_game.tscn")`。
- **牌桌只是服务端**：直接进后 `players` 为空，必须再下 `c_start`（`GameStartCommand.do_init_setup` 遍历 `users`，再 `ensure_min_players(2)` 补 AI）。
- 发指令走 `GlobalConsole.command("c_xxx", [args])`（等价于控制台手敲，不绕过 `command.tres` 的校验）。
- **eval 三条铁律**：①一个语法错误就让进程进 `break`（`await` 打成 `owait` 即触发），不会自愈；②单次 eval 的 await 合计别超过 ~8s，超时被中止后残留协程会二次报错；③取属性用 `Object.get("HP")` 安全取值，缺属性返回 null 而不抛错。
- `break` 的唯一恢复：`project_manage(op="stop")` → 重新 run → 重新 `c_start`，**比分全丢**。

## 九、双进程真人局

服务端 = 编辑器 `project_run`（随机端口）；客户端 = 独立 exe（完整菜单，给真人用）。

顺序不能反：**真人先点"开始游戏"**（它会 `random_create()` 起随机服务器），再 `c_connect_to(ws://localhost:<端口>)`。原因：`System._ready()` 无条件 `call_deferred("start_server")`，菜单阶段就连接会被它自己顶掉。

- 服务端读端口：`get_node("System").transport.network_manager.url`。
- `users` 顺序 = 插入顺序，服务端 id 1 → 玩家 2；客户端 → 玩家 3；`users==2` 时不再补 AI。
- `game_eval` 只落在编辑器进程（独立 exe 无调试器通道）；保险起见每轮核对 `OS.get_process_id()`。
- 沙箱看不到 Godot 进程：判断真人是否已连，只能读服务端 `users`。

## 十、计时器（决定能不能打真人局）

`stage.time_limit > 0.0` 才起计时器；`StageMain` 60/30s、`StageDefense` 30s 起且**动态递减**（每回合 −5，下限 5s）、`StageDiscard` 10s、`StageDying` 10/4s。

**结论（实测）**：本模式下"看状态 → 决定 → 出牌"要 1–3 次工具往返，实测多次超过守区攻防的动态时限 → 游戏替我放弃响应 → 白掉生命与精神。**要么关掉计时器，要么只把 AI 当慢速回合制对手。**

另外：轮到**我**行动时绝不能用系统级 `Start-Sleep`（那正是响应窗口）；只有对方持回合时才可睡。
