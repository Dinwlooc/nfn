## 一、群体攻击（完整链路）

| 环节 | 实现 | 状态 |
|---|---|---|
| 结算命令 | `System/Command/LightCommand/GroupAttackCommand.gd`：INIT 缓存威力与逐目标 `max(0, power−响应牌威力)`；RESOLVE 先追加弃置再**逆序**追加伤害；DONE 发 `group_attack_resolved(power, ids, hp[], mp[])` | ✅ 伤害数学有判据 |
| 响应窗口 | `System/Stage/TempStage/StageGroupAttack.gd` + `GroupAttackStageRequestCommand`：只**登记**响应牌（不动牌），全部表态后入队结算 | ✅ 超时路径有判据 |
| 响应请求 | `OperationRequest.RespondCard`（`respond_card`，带 card_id） | ✅ 序列化往返 PASS |
| 规则校验 | `RuleCardUsage.can_use_card_in_group_attack`：本人 / 在手牌 / 卡牌开关 `group_attack_available` | ✅ 两条分支有判据；**H 终审抓到开关原本恒失效**（键不在 `_allowed_validator_keys`，`RESPONSE_FORBIDDEN` 是死分支），已修 |
| 渲染通道 | `RenderRequest.GroupAttackNotify{START,UPDATE,RESOLVED,FINISHED}` → `RenderAreaCenter` → `RenderStateManager`（FINISHED 清空快照） | ✅ 往返 + 消费 + 超时通知 |
| 数值验证 | — | ❌ 未跑真局 |

**关键设计决定**：响应牌留在手牌，由结算命令统一弃置（若走 `RuleCardPlay` 会先把牌移出、令命令自己 fail 出零伤害）；阶段只入队不结算，收尾交给下一次 `refresh_response`（照搬 `StageDefense` 两段式）。

**新发现（2026-10-27）**：`.gd` 里**没有任何代码实例化 areaface 场景**——`areaface_hand.tscn` / `areaface_defence.tscn` 等只以节点形式挂在 `main_game.tscn` 上（`Control/AreaHand`、`Control/AreaDefence`）。`RenderAreaPlayers` 在运行时为非本地玩家创建的 hand / defence / ability 三个区域，**结构上就拿不到 face**。所以"技能区缺 face"不是技能区独有：**运行时创建的玩家区全都没有 face**。补的时候要么给定这些区域建 face（照 `areaface_hand` 的结构），要么加一条运行时按区域名取 face 的路径（这是结构性决定，需要 Owner 拍板）。

## 四、下一件能做且不需要 Owner 决策的

1. ~~群体攻击的 `power` 在源卡已进弃牌区后是否仍正确~~ **已判：与区域无关**。判据：同一张 `default_basic_attack` 依次处于 hand / discard / hand，`get_power()` 三次相同且 > 0（场景判据 PASS）。所以 INIT 阶段读威力不受"源卡已被移入弃牌区"影响。

## 五、停在这里的原因（需 Owner 一句话）

判据（可复跑）：`python .dsh/custom_tools/measure/_tool_ground.py group_attack_notified`（以及 `group_attack_resolved`）都返回 **`WARN no_connect_site`**——信号声明与发射都在，全仓没有 `connect` 点。

意思是：**数据和状态已经送到渲染层了，缺的只是"长什么样"**。两件都只差视觉决定：

1. 技能区（`ability`）的 face 场景：区域类已在，缺 `.tscn` 与挂进 `main_game.tscn`。
2. 群体攻击表现：目标高亮 / 待表态提示 / 结算飘字，接到 `group_attack_notified` 即可。

给出样式（或一句"照某张牌的样子来"）就能继续，不需要额外设计授权。
